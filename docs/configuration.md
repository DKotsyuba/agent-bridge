# Configuration

Bridge reads two TOML files, both written and owned by the operator. Neither is
ever generated by the product, and secret values never belong in them except the
grant tokens of the daemon file, which should therefore be mode `0600` and owned
by you (the daemon does not enforce this). Parse errors report only a line number, never text that could quote a
value. Paths are absolute. A worked example is in
[Getting started](getting-started.md#5-configure).

| File | Read by | Contents |
|---|---|---|
| daemon configuration | `bridge-native-daemon` (and plain `bridge-daemon`) | database, socket, limits, grants, `[adapters]` |
| interfaces configuration | `bridge-root-relay` and `bridge` | core socket, operator, root relay, Telegram, notification ledger |

## Daemon configuration

```toml
database = "/ABS/state/bridge.db"       # SQLite custody database
socket   = "/ABS/state/core.sock"       # created 0600; a live endpoint is refused

[limits]
max_admitted_events = 10000             # required
# optional, defaults shown:
# max_pending_per_publisher = 10000
# max_pending_latest_per_recipient = 128
# max_retained_events = 5000000          # hard cap on retained dedup history, never evicted
# max_connections = 64
# idle_timeout_ms = 60000
# request_timeout_ms = 10000
# write_timeout_ms = 10000

[universal_limits]                      # optional; v1 identities, never a job timeout
# max_open_routes = 10000
# max_retained_routes = 100000
# max_registration_requests = 1000000
# max_delivery_scopes = 100000
# max_lifecycle_requests = 1000000
```

The last `max_admitted_events / 4` slots (at least one) admit `keep_all` events
only. Every limit must be positive; `max_open_routes` may not exceed
`max_retained_routes`. Exhaustion refuses new admission; nothing is evicted.

### Grants

Each `[[grant]]` (`[[grants]]` is accepted too) authenticates one identity.

```toml
[[grant]]                               # publisher realm
token = "<unguessable secret, at least 16 bytes, unique>"
publisher = "sample-producer"           # also the source tag in rendered events
recipients = ["host/codex/namespace/session"]   # canonical addresses, or "*"
kinds = ["worker.completed"]
modes = ["message", "auto"]             # message, inject, auto
policies = ["keep_all", "latest"]       # keep_all, latest, batch

[[grant]]                               # operator realm
token = "<a different secret>"
publisher = "bridge-ops"
admin = true                            # empty allowlists; cannot publish
recipients = []
kinds = []
modes = []
policies = []
```

- A canonical address has four slash-separated components,
  `host/harness/store-namespace/session`, where `harness` is `codex` or
  `claude-code`. A component containing `/` or `%` is percent-encoded
  losslessly (`%2F`, `%25`). `"*"` permits any well-formed address; delivery
  still requires a qualified native endpoint.
- The `publisher` is the stamped identity of every event. Rotate a token without
  changing it. A publisher used as a source tag must be a valid tag.
- Publisher allowlists are the constraints on any publication, including v1.
  An operator grant must have empty allowlists and cannot enable `producer_v1`.

### Producer v1 permissions

v1 mutations are opt-in per grant. Without `[grant.producer_v1]` a grant keeps
the legacy behavior and acquires no new permission.

```toml
[grant.producer_v1]                     # directly after the [[grant]] it extends
registration = true                     # fresh native call registration (default false)
reply_policies = ["self"]               # self; add shared_session only deliberately
native_scopes = ["*"]                   # or exact host/harness/store prefixes
direct_address = false                  # allow publishing to an explicit address
delivery_scopes = true                  # producer lifetime create/retire
assertion_audiences = []                # configured backend audience names
```

Use narrower prefixes, recipients, modes and kinds when the deployment allows.
`reply_policies = ["shared_session"]` lets a Claude child that shares its root's
session address receive replies there; it never grants root identity or any
product permission. See [Producer integration](producer-integration.md).

## Native adapters

`bridge-native-daemon` adds an `[adapters]` table to the same file.

```toml
[adapters]
channel = "/ABS/state/ch/c.sock"        # socket inside a private 0700 directory
host_id = "this-host"                   # host component of every attested address
# sandbox = "/usr/bin/sandbox-exec"     # confinement launcher; without it Codex message is refused
# intermediates = ["/bin/sh", "/bin/bash", "/bin/zsh", "/bin/dash", "/usr/bin/env"]
# max_call_age_ms = 600000              # age of a hook record a caller may join

[[adapters.harnesses]]                  # one policy per harness product; no store or executable
harness = "ClaudeCode"                  # or "Codex"
namespace = "claude-main"               # native_store_namespace of its addresses
inject = true                           # root hook context injection is supported
message = true                          # the message carrier is supported

[[adapters.relays]]                     # optional: the root relay build
path = "/ABS/home/releases/<version>+<label>/bin/bridge-root-relay"
sha256 = "<64 hex>"

[[adapters.audiences]]                  # optional: detached backend assertions
name = "backend-a"                      # opaque name, also granted in assertion_audiences
producer = "sample-producer"            # authenticated producer identity
executable = { path = "/ABS/backend", sha256 = "<64 hex>" }
```

No store path and no harness executable is declared. A hook counts as a hook of a harness
only when its parent chain reaches a process of that harness product (through the
allowlisted `intermediates`, as the same user) for a harness kind that has a policy. That
process must be positively marked as the product (its resolved executable path names `codex`
or `claude`, or matches an explicit `executable_markers` entry), run from a regular
file owned by you or root that no group or other user can write and that was not changed
since the process started, and its own store, taken from its environment (`CODEX_HOME`,
`CLAUDE_CONFIG_DIR`, else `$HOME/.codex` or `$HOME/.claude`), must be a canonical directory
you own that no group or other user can write (a symlink or non-canonical spelling is
refused, and the store is checked again at every use). A fresh session in any such store
registers from its own lifecycle hook: there is nothing to enroll and no runtime
operation to enroll with. Addresses use the policy's single namespace; an equal session id
from a second live incarnation is refused as a conflict. The marker is best-effort
identification, not authentication: same-user code that can fake the marker or the
hook is the documented excluded hostile same-user case. The [adapter
guide](../crates/bridge-adapters/README.md) explains the trust model.

Only Bridge's own privileged components keep digest qualification: the `relays` and
`audiences` builds are hashed at daemon start and again, in the background, whenever a
configured file's identity changes (an update that leaves the approved bytes identical
recovers by itself), and a *different* build is refused until you update its digest and
restart the daemon.

### Migrating a configuration written for store and build allowlists

Earlier releases declared `[[adapters.profiles]]` with a store, a harness executable path,
its SHA-256 and an optional vendor `signature`. Those entries still load, as migration
input only: they authorize nothing (no store or executable is allowed or refused because of
them, and `signature` is no longer checked). The daemon logs and `bridge doctor` reports one
note per legacy profile and derives one harness policy per harness from it: its single
namespace and the union of the `inject` and `message` flags of its executables. Two
different namespaces for one harness are ambiguous and the daemon refuses to start until
you configure `[[adapters.harnesses]]` explicitly; configuring both is refused too. A
`[[adapters.owner_relays]]` table from an earlier release is not an error and not a
setting: it is read and discarded, joins no digest cache, takes no part in owner admission
and authorizes nothing, and the daemon log and `bridge doctor` report it as
`legacy_owner_relays_ignored` (the owner route now trusts only the same-user direct-parent
owner running a trusted, unchanged executable) until you delete the table. Prefer
replacing the legacy entries with one `[[adapters.harnesses]]` entry per harness. Note that a
policy now applies to every build of the harness, not only to the digests you listed.

### Native owner route

A supervisor that launched and owns a live Codex or Claude Code process may publish a
private socket for it and name the socket in that process's own environment as
`BRIDGE_NATIVE_OWNER_SOCKET`. Bridge then wakes the recipient through that owner, only
while the recipient is positively idle, instead of through a legacy route. The variable
is only a locator: Bridge connects only if the socket is a canonical absolute path
owned by the daemon's user with mode `0600` in a private `0700` directory, and the
connected process is the exact direct parent (PID, start time and user) of the
attested harness, and that owner runs from a trusted executable: a regular file owned by
you or root that no group or other user can write and that was not changed since the owner
process started. No owner path or digest is configured, and no enrollment exists; an
`owner_relays` entry from an earlier release is ignored and authorizes nothing.

- A harness whose environment names no owner keeps every legacy route unchanged.
- A present locator that is malformed, not valid UTF-8, untrusted or unavailable
  holds the attempt. So does an environment that cannot be read. There is no fallback
  to a queue, application or inbox route.
- One request (`thread_id`, `call_id`, `text`, `native_pid`, `native_start_time`,
  `wake_only`) and one receipt (`call_id`, `state`, `protocol`, `native_id`, `reason`)
  are exchanged per attempt, framed by a four-byte little-endian length, at most 1 MiB
  encoded and 98304 bytes of manifest text.
- The exchange has one absolute 35-second budget. Nothing is sent unless the core
  attempt still has at least 35 seconds left, checked before connecting and again
  immediately before the first byte. After the request is written only a correlated,
  exactly shaped receipt is anything but an unknown outcome, and an unknown outcome is
  retained and never resent. An accepted receipt means the native owner observed
  acceptance, not that the context was processed.

Do not share a backend credential or executable qualification with an untrusted
frontend: an audience entry is a deployment trust declaration, not a permission.

## Interfaces configuration

One closed file (unknown keys are refused) used by the relay and the CLI.

```toml
core_socket = "/ABS/state/core.sock"

[operator]                              # absent: operator commands are disabled
token_file = "/ABS/state/secrets/operator-token"     # holds an admin grant token

[root]                                  # absent: the relay refuses to start
socket = "/ABS/state/rl/relay.sock"     # directory must be 0700 and yours
token_file = "/ABS/state/secrets/relay-token"        # holds the relay's publisher grant token
channel = "/ABS/state/ch/c.sock"        # adapter channel; absent: every request refuses
# max_caller_age_ms = 600000
# max_body_bytes = 16384                # at most the core payload bound

[[root.callers]]                        # at least one
host_id = "this-host"
harness = "claude-code"                 # codex or claude-code
native_store_namespace = "claude-main"
# native_session_id = "..."             # exact session; absent matches any root session of the store
recipients = ["*"]                      # canonical addresses or "*"
modes = ["message", "inject", "auto"]
kinds = ["bridge.message"]

[telegram]                              # optional outbound-only owner notification
token_file = "/ABS/secrets/telegram-bot-token"       # 0600, owned by you
chat_id = "123456789"                   # numeric id or @username
# api_base = "https://api.telegram.org" # the only accepted value
# timeout_ms = 15000                    # 1..=120000

[notify]
ledger = "/ABS/state/notify-ledger.json"             # one per core, 0600
# max_attempts = 3                      # 1..=10
```

Secret files are regular files you own, at most 4096 bytes, with no group or other
access; links are refused. Only attested *root* actors acting as their own session
match a caller policy; exact-session entries take precedence over whole-store ones.
Without `[telegram]` an owner notification reports `known_unsent: owner not
notified` and the incident stays open and visible.

## Environment

- `TMPDIR`: where tests and the installer create temporary files; keep it short.
- `AGENT_BRIDGE_HOME`: default install home for `install.sh` (otherwise
  `~/.agent-bridge`).
- `BRIDGE_TEST_NODE`: absolute path of a Node.js executable, required by the full
  workspace tests (the deterministic Desktop regressions); nothing is downloaded. Not needed to run Bridge or the SDK.
- Probe variables (`BRIDGE_BIN_DIR`, `BRIDGE_Q4_PAID`, `CODEX_EXE`, `CLAUDE_EXE`)
  belong to the manual [qualification probes](../crates/bridge-adapters/README.md).
