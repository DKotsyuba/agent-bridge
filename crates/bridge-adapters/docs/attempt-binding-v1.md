# Bridge attempt-binding private wire v1

This private B1 encoding is for coordinated attempt binding. It does not by itself establish Run admission or managed delivery qualification. The existing [native producer contract](producer-native-v1.md) remains unchanged. It applies only to the Linux same-UID protected native channel and explicitly qualified stdio frontend. It adds operations to the existing producer NDJSON envelope, `api_version: 1`, with distinct names and strictly decoded parameter/result types. Existing operation DTOs and their unknown-field rejection do not change. All strings below are UTF-8, nonempty, at most 256 bytes, with no control characters unless specified. Timestamps, sequence and inode/ticks are unsigned integers; IDs are opaque and case-sensitive. Hashes are 64 lowercase hex digits. UUIDs are canonical lowercase text. Object fields are required except where explicitly nullable; unknown and duplicate fields reject.

## Store, route, configuration and authentication

A fresh private route journal receives a random UUID `store_id`, durably written before the first new operation is accepted. Route schema 4 and the separate numbered managed journal are committed independently; managed-journal failure does not poison legacy route writes. Migration of a v1 journal creates it once atomically; rollback/clone is outside anti-rollback guarantees. A corrupt journal refuses operation. A missing journal creates a new identity; requests pinned to the former identity refuse, and an operator must establish the new identity out of band. Every new request except discovery carries `version: 1, expected_store_id: UUID`. Every success/error result of a new operation carries `version: 1, store_id: UUID`; mismatch refuses before any mutation. Discovery `attempt_binding_capabilities_v1` has `{version:1}` and returns `{version:1,store_id,capabilities:["attempt_launch_v1","launch_assertion_v1","namespace_retirement_v1"],issuer_epoch}` only when implemented/enabled. On Linux the capability list also includes `run_actor_lookup_v1` and `run_actor_recovery_status_v1`; `managed_owner_v2` is included only for an explicitly configured owner-v2 route matching this store. Clients pin store ID and route out of band before first use; discovery is not authority and cannot replace a previously pinned store after failure.

`[[adapters.run_readers]]` has `producer` (the exact authenticated producer of observations this reader may query), `reader` (the distinct producer identity authenticated by the existing credential grant), and `executable = { path = "/absolute/path", sha256 = "..." }`. The registry verifies same kernel peer UID, actual executable, warmed digest and loaded-build freshness as for existing backend audiences. Distinct entries are explicit; names never prove a peer. Reader grant and executable both must match; no cross-UID/remote transport. The original consuming audience may recover its own observation with the same peer/build/audience authentication as consumption. Abort is only for the original configured consumer, including a pre-consume abort; the audience is explicit in the request and verified against its producer. Reader cannot abort merely by being a reader.

`[[adapters.managed_tools]]` has `producer`, `server`, `commands` (nonempty list of exact names), and `frontend = { path = "/absolute/path", sha256 = "..." }` identifying the qualified stdio frontend executable. Its kernel peer identity and loaded build must match; both standard input and output must be pipes or sockets, bracketed by equal full kernel identities. Socket stdio must have its inode in the kernel Unix-socket table; pipes remain valid. The frontend and consumer audience may share an executable path and SHA-256 build; the Run reader and managed owner builds remain distinct from both. Frontend authority requires the configured loaded build, stdio transport and a verified managed Codex/Claude harness ancestry; Bridge durably records the full frontend incarnation before accepting its first frontend operation. A consumer must match its configured audience build and prove a complete, stable kernel ancestry through PID-namespace init, with no recorded managed harness or frontend incarnation and no managed-launch environment marker on any same-UID process in that chain. Each proven consumer incarnation is also durably fenced from later frontend authority. A process cannot switch between those roles after reparenting, exec or a Bridge restart. Missing, unreadable, truncated, cyclic or changing ancestry, identity or environment evidence refuses; the launch marker is used only to deny, never to grant authority.

On first managed enable, Bridge atomically initializes a private, store-bound frontend-role journal with a kernel-tick bootstrap point. A consumer whose configured audience shares a frontend path or build must have started strictly after that point; an earlier or equal-tick process receives `relaunch_required` with recovery `none`. Enable managed mode first, then (re)start the Pool resident. Same-boot Bridge restarts retain the original point and frontend fences and do not require another resident restart. A new boot/PID namespace or missing role journal establishes a fresh point and requires a newly started shared-build resident; corrupt or uncertain role state refuses managed roles. Role fences are pruned only after the exact process incarnation is proven gone. The configured build must itself enforce stdio-only frontend operation; same-UID hostile trusted components remain outside the guarantee. A proof for `command_name` requires observed `tool_name` exactly `mcp__{server}__{command_name}`, with both server and command in this configured mapping; ambiguous/duplicate mappings refuse configuration. Registration binds the same `command_name` as preparation. This is association with a protected native call, not independent verification of tool argument bytes. Unqualified role, transport, host, or actor refuses. Capability negotiation must not be advertised until all these fences work.

## Shared values

`Incarnation = {host_id:string,boot_id:UUID,pid_namespace_inode:u64,uid:u32,pid:u32,start_ticks:u64}`; numeric identity values except UID are positive. Namespace must equal Bridge's own PID namespace. Managed hook selection, caller claims, currentness, binding recovery and owner lookup use this full kernel identity; historical rows without it cannot authorize managed work. Legacy second-resolution fields remain only for the unchanged legacy protocol. `Actor = {address:string,role:"root",native_id:string,epoch:u64}`. `Observation = {incarnation:Incarnation,launch_id:UUID,actor:Actor,native_call_id:string,tool_name:string,observed_at_ms:u64,expires_at_ms:u64}`. Launch is correlation, not a bearer credential. Observation is taken only at original hook, from direct exec environment between equal kernel identities. No process snapshots can repair missing initial evidence.

`Validity` is `"current"` or `"historical"`; current requires this issuer epoch, unexpired original observation, same live full incarnation, same actor/binding/epoch and no abort. Restart changes issuer, making prior observations historical. Bridge preserves and returns the original captured context even when the hook precedes Run bind; Bridge does not read the Run store or use a bind callback. Run R2 owns the durable bind/currentness decision and returns `attempt_not_ready` until bind is durable, then may admit using that same still-fresh original observation. Freshness is determined by Bridge using Bridge's clock and returned validity; Run must not compare its own clock against Bridge timestamps. A historical or aborted receipt never authorizes a new admission.

The response is the existing `Response` envelope with `result.op` matching the request operation; `result.value` is a tagged `Outcome`: `{"status":"ok","value":...}` or `{"status":"error","error":{"version":1,"store_id":UUID,"code":string,"recovery":string}}`. Authentication/frame errors before store access use the existing bounded outer `ApiError`; no detail contains inputs or secrets. A completed `Outcome::error` is a protocol-level result, not an instruction to repeat an uncertain operation. `recovery` is `same_key_lookup`, `fresh_invocation`, `operator`, or `none`.

## Operations and results

* `prepare_native_context_v1`: `{version,expected_store_id,expected_issuer_epoch,invocation_key,command_name,native_proof}`. `native_proof` is the existing `CallEvidence` tagged shape; only actual protected direct stdio origin qualifies. Returns `{version,store_id,bridge_context_ref,invocation_key,expires_at_ms}`. The Pool frontend obtains `expected_issuer_epoch` from `attempt_binding_capabilities_v1` and refreshes it after a stale-epoch refusal. Bridge rejects a different issuer before reservation. Reserves one original hook without spending it. Exact replay returns the same reference and expiry; changed intent conflicts. Registration and expiry serialize under the registry writer. Expired unregistered reservations are sealed with permanent invocation and original-source fences before call-capacity admission; registered or consumed work is never TTL-released.
* `context_lookup_v1`: `{version,expected_store_id,producer,bridge_context_ref,invocation_key}`. Configured Run reader only. Returns `{version,store_id,bridge_context_ref,invocation_key,observation,issuer_epoch,validity}`. No mutation authority; mismatched producer/ref/key refuses. An expired/sealed context is not current; once an unregistered context is compacted, later lookup returns `assertion_historical` rather than reconstructing it.
* `register_launch_assertion_v1`: `{version,expected_store_id,bridge_context_ref,invocation_key,command_name,security_digest,audience,nonce,native_proof}`. Exact authenticated same stdio frontend and original reserved source required. Returns `{version,store_id,assertion_key,invocation_key,issuer_epoch,expires_at_ms}`. Assertion key is secret and stored only in the mode-0600 private managed journal while its original observation can still be current (lookup uses its hash); exact current replay returns the original key and cannot renew expiry. Expiry, abort and issuer change remove plaintext keys; consumed receipts remain recoverable as historical until namespace retirement. Neither key nor other secret is logged. Changed digest, command, audience, nonce or source conflicts. Existing legacy registration is independent and unchanged.
* `consume_launch_assertion_v1`: `{version,expected_store_id,assertion_key,invocation_key,security_digest}`. Envelope `request_id` is `consume_request_id`. Authenticated configured audience consumes once; association is durable before response. Returns `{version,store_id,receipt,validity,aborted}`. `receipt = {producer,consume_request_id,invocation_key,security_digest,observation,issuer_epoch,consumed_at_ms}`. Exact replay returns same receipt, never renewed, and freshly evaluated validity; changed association conflicts.
* `observation_lookup_v1`: `{version,expected_store_id,producer,consume_request_id,invocation_key,security_digest}`. Configured Run reader or authenticated original consumer only. Returns `{version,store_id,receipt,validity,aborted}` with the exact immutable receipt and currentness checked anew. Absence is `binding_unavailable`, a snapshot, not a fence. After restart it is historical. Only a previously durable Run admission may use historical lookup for its recovery.
* `consume_launch_assertion_abort_v1`: `{version,expected_store_id,producer,consume_request_id,invocation_key,security_digest,audience}`. Authenticates the original configured consumer; serializes with registration/consume. Returns `{version,store_id,aborted:true,receipt:null|receipt}`. It durably records the exact intention even if absent; delayed registration/consume rejects. If consume won, it returns and seals the original receipt; this does not revoke an existing Run admission. Exact replay returns the same result; changed digest/key/audience conflicts. Tombstones do not expire. An already compacted unconsumed fence can be durably upgraded to the exact authenticated abort intention. Context admission reserves bounded journal space for its later receipt and abort; capacity exhaustion refuses before side effects. If no registration was submitted, an abandoned prepare needs only a local continuation fence; the original invocation key is never reused and Bridge later seals its expired unregistered reservation. No invented pre-registration digest or consume abort is needed.
* `retire_attempt_namespace_v1`: `{version,expected_store_id,producer,issuer_epoch,retirement_key}`. Configured Run reader only. The reader's authenticated request attests that Run and Pool have settled all admissions and all outstanding recovery for that producer and issuer epoch. Bridge durably retires that namespace, converts its retained contexts/receipts to permanent rejecting key fences, and returns `{version,store_id,producer,issuer_epoch,retirement_key,retired_count}`. Exact replay is idempotent; reuse of the retirement key for another producer or issuer conflicts. After retirement the old context, invocation, assertion, consume and full original native source-use keys reject permanently; their receipts are no longer available, so Run R2 must call this only after recovery is definitively complete. Original-source fences bind full kernel identity, actor address/native ID and call ID independently of issuer and endpoint epochs, so restart cannot make the same source reusable. A caller cannot retire the current issuer epoch, and an issuer with no retained contexts returns `binding_unavailable` without recording a retirement. An aborted consumed context retains its exact abort fence, so abort replay after retirement returns `aborted:true` and `receipt:null`. This new operation is a required Run R2 integration interface, not a TTL cleanup or proof that an admission has settled.

Codes: `unsupported_version`, `capability_missing`, `transport_unsupported`, `role_unqualified`, `relaunch_required`, `peer_not_authorized`, `audience_mismatch`, `binding_unavailable`, `attempt_not_ready`, `attempt_mismatch`, `actor_mismatch`, `route_mismatch`, `assertion_stale`, `assertion_historical`, `invocation_spent`, `intent_conflict`, `request_in_progress`, `capacity_exhausted`, `aborted`, `recovery_required`. Refusal never embeds a launch, proof, secret, payload, path or peer-provided text. `intent_conflict` and `aborted` use `none`; stale/spent uses `fresh_invocation`; unresolved durable state uses `same_key_lookup`; unreadable/corrupt store or pinned store mismatch uses `operator`; an uncertain journal commit uses `same_key_lookup` after recovery; unauthorized/unsupported uses `none`.

Managed ancestry checks bracket kernel reads and require each parent start tick not exceed its child. The current safe dependency set does not expose pidfd/SO_PEERPIDFD; kernel peer PID reuse between peer-credential acquisition and inspection remains a residual requiring a separately reviewed safe wrapper.

## Managed clients and owner recovery

Every managed SDK method requires an explicit pinned Bridge server executable path and SHA-256; the connected kernel UID, PID, full incarnation and live executable inode are verified before credentials are sent. Managed methods never automatically retry an uncertain write. See the [SDK transport contract](../../bridge-sdk/README.md#transport-and-errors).

For Linux managed egress, authenticated Run receipts, single-effect owner v2 dispatch, durable lookup and abort, and the separate Run custody reader are described in [managed owner configuration](../../../docs/configuration.md#managed-owner-v2). An unknown native effect is retained and never resent; an absent Run lookup is not a fence.
